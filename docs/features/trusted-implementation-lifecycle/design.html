Trusted Implementation Lifecycle — Technical Design

An always-on parent extension handles an idle direct human mutation request before the primary agent, creating a durable fail-closed transaction with one path-confined writer, immutable verification/review evidence, bounded repair, and human integration.

Architecture approval brief

Decision
Make one always-loaded ImplementationLifecycleController the mutation admission and delivery-completion authority for direct Pi sessions.
Recommendation
In input, accept only an idle direct interactive TUI user request with explicit edit/implementation intent, atomically create the root lease, return handled, and start the transaction before any primary agent runs. For all other turns, a deny-by-default tool_call barrier permits audited read-only tools only, blocks unauthorized mutations without creating authority, marks the whole batch blocked, and aborts the primary run. Capture a complete clean-or-dirty Git snapshot, launch path-confined child roles, verify a disposable candidate snapshot, persist the immutable evidence tuple, and return a human integration decision.
Goal/outcome
Implementation requested through normal Pi conversation cannot mutate or complete outside a candidate-bound verifier and independent review lifecycle.
Proposed shape
ImplementationLifecycleController owns admission and policy; DeliveryRunStore alone owns the atomic cross-process root lease and durable evidence; CandidateWorkspace captures complete nonignored base/candidate trees and disposable verification snapshots; HeadlessPiRoleRunner launches no-discovery children with one controller-owned path guard extension; ExplicitVerifier owns executable gates; the primary session owns user communication only.
Why this shape
The input boundary is the only point that can bind trusted direct-human authority before an agent turn; tool_call is the final effect boundary for every other turn. Parent orchestration plus controller-owned role profiles prevents the writer or candidate from changing policy, verification, reviewer authority, receipts, or integration state.
Approve
Add interactive-only admission, provenance/effect-bound read-only primary tools, atomic root lease, complete snapshot, one guarded no-shell writer, protected verification closure, controller-profiled read-only reviewer, two pre-counted repairs, process-stopped cancellation/reload reattachment, durable fail-closed records, and zero-integration terminal outcomes.
Not building
A /deliver command, skill-triggered enforcement, mutable worker fan-out, automatic merge, unbounded retries, project-local controller policy, or a shared Alphonse runtime package.
Risks/blockers
Child Pi processes retain host identity and provider credentials unless separately contained. Version one therefore omits writer bash/PowerShell and confines built-in edits through a controller-owned guard extension, but this remains trusted-local rather than an OS sandbox. Intent classification is authority-sensitive and must fail closed on ambiguity.
Readiness
Approved by the product owner on 2026-09-01; implementation must fail closed when repository, verifier, candidate, or child-role proof is unavailable.
Pressure

The primary session cannot be both an unrestricted writer and its own delivery controller

Current extensions provide useful pieces, but none owns the complete authority-to-candidate lifecycle or prevents a normal agent from writing before those pieces run.

  • agent-jobs can persist detached processes but marks model/process termination rather than accepted software quality.
  • verify runs after interactive agent completion and intentionally skips headless contexts; it is not an explicit candidate-bound service.
  • worktree-manager creates feature branches from a configured base and may copy local hidden environment by default; delivery needs a current-base detached candidate with no environment copy.
  • before_agent_start can influence prompts but cannot enforce behavior; tool_call can block the actual edit/write/bash operation.
  • A child Pi process discovers the same global extensions unless launched with a restricted profile, creating controller recursion and capability leakage.
  • A session entry is conversational and ephemeral; restart-safe run state must live outside the transcript.
Rejected obvious seams

Do not rely on implement-task to remember the lifecycle, run verification only in agent_end, let the primary session mutate and review its own tree, or load the delivery extension inside writer/reviewer children. Each choice leaves self-certification or recursive authority in place.

Owning seam

ImplementationLifecycleController owns mutation admission and terminal truth

Existing extensions become collaborators behind one controller instead of independent advisory features.

  1. ImplementationLifecycleController
    The input handler accepts only idle direct interactive TUI user input with explicit mutation intent, asks for clarification on ambiguity, atomically acquires the canonical-root lease, returns handled, and starts one run before the primary agent. before_agent_start selects controller-owned path-confined controller-owned read/grep/find/ls wrappers plus explicitly fingerprinted read-only tools; tool_call rejects any definition/provenance/input mismatch, blocks the remaining parallel batch, and calls ctx.abort(). Direct interactive ‘cancel implementation’ kills and waits for the child process group; session_before_switch refuses new/resume/fork until terminal, and reload adopts only a proven-dead lease, reconciles child evidence, and terminates non-favorably; it never resumes to the lease.
  2. DeliveryRunStore
    Is the sole manifest and receipt writer. It atomically acquires one cross-process lease per canonical Git common root, persists one atomically updated per-run manifest with append-only attempt evidence under the Git common directory at pi-delivery/runs; its terminal evidence becomes immutable and guards the active lease with nonce, PID, and process-start identity, and records trusted interactive request ID, authority digest, complete snapshots, exact primary/writer/reviewer tool/rubric/resource-profile digests, protected verification closure/results, supplied-review-input digest, repairCount, child process-group/exit evidence, cancellation, and terminal reason. It rejects stale or mismatched receipts.
  3. CandidateWorkspace
    Uses an alternate private Git index to capture the complete current nonignored clean-or-dirty working state—including staged, unstaged, untracked files, modes, symlinks, deletions, and renames—as a base tree without changing the user index. It creates one detached no-copy sibling worktree from that tree with hooks and fsmonitor disabled, freezes candidate trees, creates a disposable verification worktree from each candidate tree, and removes only manifest-owned paths.
  4. HeadlessPiRoleRunner
    Uses a controller-local stopped-start process-group primitive with durable pending-launch intent plus pre-release PID/start persistence, complete output hashing, TERM→KILL, and group-absence proof; agent-jobs remains independent. Each child disables discovered extensions, skills, prompt templates, and context files, then loads one explicit controller-owned role-policy extension and a controller-injected hashed role rubric. Writer/repair receives path-confined read/ls/edit/write only—no bash/PowerShell—and cannot reach Git/run-record paths. Reviewer receives path-confined read/ls plus a bounded report tool; candidate instructions are data only. Parent wrappers, never children, write authoritative logs and receipts.
  5. ExplicitVerifier
    Exports explicit verification as passed | failed | missing | timeout | mutated. It freezes and hashes the base verify script, package scripts/lockfile, CI/test/build configuration, and existing test suite as a protected closure; authorized exceptions are part of authority. It rejects candidate changes to that closure and exports the candidate into a standalone disposable snapshot without shared Git metadata, runs the frozen base gate and rejects added or changed tests whose execution cannot be proven, records command/result/output digest, recomputes the tree to detect side effects, and rejects missing, changed, weakened, timed-out, or mutating verification.

Causal path

A blocked primary mutation becomes one detached candidate transaction

The path keeps authority in the original session and mutation in a child workspace while every acceptance signal binds to one candidate identity.

  1. Capture authority
    While Pi is idle, input accepts only a direct interactive TUI request with explicit mutation intent, canonicalizes the Git root, atomically acquires its cross-process lease, persists trusted request ID/source/digest, returns handled, and immediately acknowledges the run. Ambiguity asks once; print/JSON fails closed.
  2. Intercept mutation
    For every non-authorizing primary turn, the controller selects its own path-confined read wrappers plus tools whose exact definition/provenance/effect fingerprint and inputs are audited read-only. Any override, mismatch, edit/write/bash/PowerShell/custom/command/unknown effect is blocked without a run; the extension marks the parallel batch blocked and calls ctx.abort.
  3. Prepare candidate
    CandidateWorkspace uses a private alternate index to capture the complete current clean-or-dirty nonignored state as a tree, records modes/symlinks/deletes/renames through Git identity, creates a detached no-copy sibling worktree with hooks/fsmonitor disabled, and stores manifest ownership before effects.
  4. Run writer
    A headless Pi child disables discovered extensions and loads only the controller-owned role guard. The writer receives read/search/edit/write without bash/PowerShell; every path is confined to the candidate and Git/run records are denied. Parent process evidence—not child output—advances state.
  5. Verify and review
    ExplicitVerifier rejects changes or additions to the frozen base verify/package/CI/test-config/existing-test closure, exports a standalone disposable candidate snapshot without shared Git metadata, runs the frozen base gate, and rejects missing/timeout/policy weakening or any resulting nonignored tree change. Only a pass starts a no-context/no-skills/no-prompts/no-discovered-extensions path-confined reviewer with a controller-injected rubric and exact profile/input digest.
  6. Repair or stop
    Eligibility is positive: a nonzero frozen command under unchanged policy/environment, or a validated candidate-evidenced Must/Should finding requiring no protected authority. For a new signature while repairCount is below two, DeliveryRunStore invalidates receipts and increments repairCount before launch. Every other failure stops.
  7. Publish terminal state
    Immediately before terminalization, the controller audits zero integration invocation and rechecks the complete primary base, candidate tree, verification tuple, reviewer profile, and supplied-input digest. DeliveryRunStore persists one terminal state before one follow-up. Direct interactive Cancel waits for process-group exit; session switches refuse while nonterminal; reload adopts only a proven-dead lease, reconciles child evidence, and terminates non-favorably; it never resumes to the lease and reconciles child evidence.

Architecture path

The parent process owns the transaction; role processes own bounded work

The diagram shows the only mutable role, deterministic evidence path, persistent state, and bounded repair feedback.

  1. An idle direct interactive TUI mutation request is handled before a primary agent turn; unauthorized tool effects are denied without creating authority.
  2. ImplementationLifecycleController atomically acquires the canonical-root lease and DeliveryRunStore records authority before CandidateWorkspace captures the complete clean/dirty base and creates the candidate.
  3. A headless no-discovery writer with one explicit path guard is the only mutable role; it has no shell or receipt-writing authority.
  4. ExplicitVerifier overlays the protected base verification/test closure on a disposable immutable candidate snapshot; only its passing tuple reaches a no-context/no-skill path-confined reviewer using a controller-owned hashed rubric/profile.
  5. Positive eligible verifier/reviewer failures consume repairCount before at most two fresh repairs; direct Cancel waits for process-group exit, session switch refuses nonterminal state, and reload adopts only a proven-dead lease, reconciles child evidence, and terminates non-favorably; it never resumes to the lease.
  6. A final recheck of authority, base, candidate, policy/results, and review input produces one terminal record and follow-up; every integration surface remains human-owned and unchanged.
Architecture decision

Trusted direct input owns activation; the write barrier enforces no unauthorized effects

This choice is blocking because another seam would make the lifecycle optional or permit mutation before evidence ownership exists.

Proof and risk

Trust comes from negative tests and candidate identity, not agent narration

The verification strategy attacks bypass, false completion, stale evidence, repair drift, and unsafe recovery directly.

  • Input fixtures cover source, streaming behavior, idle state, explicit/ambiguous/non-mutation language, interactive TUI authority plus RPC/print/JSON failure.
  • Extension harness proves unauthorized write/edit/bash/PowerShell/custom/command and mixed parallel batches create no run, never execute, and abort; concurrent sessions race for one atomic canonical-root lease.
  • Temporary repositories prove alternate-index complete clean/dirty snapshots, modes/symlinks/deletes/renames, detached no-copy candidate, final base drift, and manifest-owned cleanup.
  • Child role-policy tests prove absolute/parent/symlink/Git-ref/run-record escapes are blocked, writer has no shell/context/skills/prompts/discovered extensions, reviewer uses a controller-hashed profile and treats candidate instructions as data, and only parent wrappers write process evidence/receipts.
  • Verifier fixtures prove frozen policy/test digest, disposable candidate snapshot, absent/timeout/changed/failing/mutating checks, complete tuple identity, and final recheck reject false merge-ready.
  • Transition tests prove positive eligibility, pre-launch repairCount≤2 with crash consumption, repeated/non-candidate stop, TERM/KILL/exit cancellation, switch refusal, proven-dead lease adoption, child reconciliation, and non-favorable termination, receipt invalidation, one terminal follow-up, zero integration invocation, and unchanged primary/ref/remote/deployment state.
  • Project regression gate remains scripts/verify.sh; agent-backed benchmark adoption follows after controller correctness.
Security boundary

The first implementation may be enabled only for trusted local repositories. --no-extensions and a worktree narrow capabilities but do not isolate the child process from the host. Untrusted unattended execution remains blocked until container or micro-VM routing is integrated and tested.

Boundary
