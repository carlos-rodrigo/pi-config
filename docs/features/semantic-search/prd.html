Product requirements Review
Product requirements · Review · Updated 2026-07-25

Find the code behind a concept before changing it

Semantic Search turns a natural-language question into ranked, explainable source ranges using a private local hybrid index.

01 · Product narrative

Find evidence without already knowing its name

  1. Moment. When an agent enters an unfamiliar repository or feature area, it needs to find the code and documentation that explain a concept before it can act safely.
  2. Friction. Exact search works only when the agent already knows the repository's names. Broad file exploration consumes time and context while still missing conceptually related code.
  3. Bet. Provide one local natural-language search that ranks code ranges using generated summaries, embeddings, lexical terms, paths, symbols, and reusable code concepts.
  4. Proof. The agent receives a short ranked candidate list with file ranges, reasons, symbols, and previews, then reads the reported range before editing.
  5. Boundary. Semantic Search finds evidence; it does not certify correctness, edit code, upload repository content, or replace exact symbol and text search.
i

Ask in product language; land on repository evidence

A query such as “where do we charge a customer?” can find checkout implementation even when the exact symbol name never appears in the question. Search remains local to the project and returns candidates that can be inspected with normal file tools.

!
Review focus

Confirm that this accurately describes the current product contract: local Ollama quality is required by default, failure is explicit, and every result remains a candidate rather than an answer to trust blindly.

02 · How it works

One local index turns concepts into readable file ranges

Indexing prepares several views of the repository; querying combines them instead of betting on one signal.

  1. 01

    Discover and protect

    The indexer finds project text files, skips binary/build/tool-state paths, honors configured exclusions, and never indexes .env secret files.

  2. 02

    Describe the repository

    Files become overlapping code chunks and semantic cards for files, functions, methods, classes, modules, definitions, and Markdown headings. Local Ollama summaries describe each card's responsibility and important relationships; unchanged summaries are cached.

  3. 03

    Represent meaning locally

    Ollama creates embeddings for raw chunks and semantic cards. The compact index is saved under .pi/semantic-search/ with project-relative paths so it can be reused safely by linked worktrees.

  4. 04

    Rank the query

    The query is embedded and compared with chunk and card embeddings. Ranking also considers lexical overlap, repository concepts, path and symbol matches, and whether the question asks for implementation rather than documentation or tests.

  5. 05

    Return evidence, then inspect

    Results show ranked paths, line ranges, summaries or match reasons, symbols, and compact previews. The next action is to read the reported range before making a change.

03 · Staying current

Content hashes decide when search knowledge is stale

Freshness is based on indexed paths, file sizes, and content hashes rather than timestamps alone.

  • A missing, unreadable, or version-old index is stale.
  • A new, changed, or removed indexable file makes the index stale—even when a changed file keeps the same size and timestamp.
  • After successful write or edit operations in a primary checkout, the session can start a non-blocking background rebuild at agent end.
  • A linked worktree can reuse a missing primary-worktree index and summary cache. Automatic full rebuilds stay off there by default to avoid repeated expensive work.
  • Composer status and /index rebuild --status expose rebuild phase, progress, best-effort ETA, completion, failure, log path, and current freshness.
04 · Trust rules

Quality failures stay visible

  • Repository summaries and embeddings go only to the configured local Ollama server; no cloud embedding service is part of the default path.
  • Default semantic search requires both generated card summaries and embeddings. Missing Ollama or models produces actionable setup instructions instead of silently returning lower-quality lexical results.
  • Lexical-only indexing, embedding-only rebuilding, and summary-free searches remain explicit diagnostic escape hatches.
  • Callers can constrain paths, include or exclude tests, cap result count, and choose whether a stale index should refresh.
  • Results explain why they ranked and always lead back to source ranges; they are not proof that the candidate is correct.
05 · Product surface

The same index supports search, orientation, and maintenance

Available surfaces

  • semantic_search and /code-search return natural-language search results.
  • repo_map groups representative files into reusable concepts such as search, auth, UI, billing, and agent behavior.
  • index_status and /index status explain freshness and index contents.
  • index_rebuild_status and /index rebuild --status expose background rebuild state.
  • /ollama-tunnel can connect Pi to a stronger remote Ollama through a localhost SSH tunnel while keeping Ollama itself bound to localhost.

Not in this product contract

  • Cloud-hosted repository indexing or embeddings.
  • Guaranteed semantic correctness or automatic code changes.
  • Indexing secrets, binaries, oversized files, generated feature HTML, hidden tool state, or configured excluded paths.
  • Replacing exact text, symbol, structural, dependency, or history search when the agent already knows what it needs.
06 · Observable proof

Search succeeds when it shortens the path to evidence without hiding uncertainty

  • A natural-language billing question ranks the checkout implementation ahead of unrelated code.
  • An implementation-location question prefers source creation code over PRDs and tests unless the query explicitly asks for documentation or tests.
  • Every returned candidate includes a path, line range, score, reason or generated summary, and a compact preview.
  • Same-size content changes are detected as stale even when timestamps are unchanged.
  • When required local models are unavailable, the user sees the Ollama URL, required models, setup commands, tunnel option, and explicit diagnostic alternatives.
  • A successful background rebuild stays quiet apart from status; a failed rebuild produces one actionable follow-up with status and log paths.

Source files remain the authority

Semantic Search reduces discovery cost. The agent still verifies returned code, follows dependency and history evidence when needed, and relies on repository tests and product documentation for correctness.
