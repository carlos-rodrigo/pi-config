Feature design Review
Feature design · Review · Updated 2026-07-25

One static shell turns approved content into navigable documentation

Protocol’s visual language, progressive section navigation, and semantic diagram motion are compiled into each standalone HTML artifact; the browser opens the result directly and no server remains running.

Product authority: approved PRD

  1. PromiseEvery PRD and design feels like one coherent documentation product while remaining a directly openable file.
  2. PressureProtocol’s visual authority comes from a Next.js application, but running or publishing an application adds infrastructure that the documents do not need.
  3. Chosen seamAdapt Protocol at generation time: inline its document shell, typography, responsive navigation, and optional behavior around the approved article.
  4. Causal pathApproved content → static template build → one self-contained HTML artifact → direct browser review with progressive navigation and diagram motion.
  5. ProofTemplate validation and browser fixtures cover wide, 320px, keyboard, reduced motion, scripts removed, interrupted motion, diagrams, and print.
  6. BoundaryNo server, routing framework, search index, database, or second canonical document format enters the system.
Pressure and seam

Presentation is compiled into the artifact, not hosted around it

The application shell is useful; the application boundary is not

Protocol provides the right visual hierarchy and navigation language. Its server, route graph, MDX pipeline, search dialog, sign-in, and feedback controls do not serve a standalone reviewed artifact.

Copy behavior, not infrastructure

prd-template.html and design-template.html own a static Protocol-derived shell. Build-time Tailwind output, navigation JavaScript, and the native motion runtime are inlined into the final file.

Causal system path

One build step produces the complete reading experience

  1. Author. The owning PRD or design skill supplies approved headings, claims, diagrams, anchors, and provenance.
  2. Compose. The HTML report designer inserts the article into one content-free Protocol-derived shell without changing its reading order.
  3. Inline. The build embeds compiled CSS, progressive section navigation, and optional semantic motion.
  4. Validate. Static checks and Chromium fixtures verify accessibility, portability, fallback behavior, responsive layout, diagram legibility, and print.
  5. Review. The reader opens the resulting file directly. No process remains running after generation.
  1. Product or architecture authority enters unchanged.
  2. The static shell adds presentation and optional behavior during generation.
  3. The resulting HTML owns all assets required for direct reading.
  4. Reduced motion, script removal, and print settle into complete static evidence.
  5. The reader navigates the artifact without a server or duplicate source.
Responsibility boundaries

Content, shell, and motion each own one kind of truth

Owning PRD/design skill
Owns narrative order, product or architecture claims, headings, diagrams, and review anchors.
Static shell
Owns Protocol typography, desktop rail, mobile disclosure, responsive measure, status presentation, and print removal of chrome.
Navigation runtime
Derives links only from authored h2[id] headings and highlights the visible destination. It adds no document content.
Motion runtime
Reveals opted-in sections or diagram stages and immediately settles for reduced motion, print, unsupported APIs, or interrupted playback.
Validator and browser fixtures
Own accessibility, overflow, no-JS, script-stripped, print, and motion-fallback proof.
Motion and fallback

Motion explains causal order and never gates evidence

  • Direct article sections opt into restrained view entry through data-motion-sections="enter".
  • Diagram stages use data-motion="flow" and ordered .diagram-reveal groups.
  • Web Animations and IntersectionObserver provide progressive behavior where supported.
  • CSS view timelines preserve scroll pacing when review tooling strips scripts.
  • Reduced motion, print, and interrupted animations force every element visible and static.
Tradeoffs and proof

Larger files buy zero deployment and stronger review portability

Decision · static shell

Inline shared presentation into every durable artifact

CSS and small progressive runtimes repeat across files.

Cost: larger HTML diffs and no cross-document search or route catalog. Benefit: direct opening, offline review, simple provenance, and no operational dependency.

  • Compiled template CSS is checked for drift.
  • The validator requires one h1, semantic landmarks, accessible figures, stable anchors, reduced motion, and print CSS.
  • Browser tests run desktop, 320px, print, no-JS, script-stripped, target feedback, scroll-paced flow, and interrupted-motion states.

The repository stores documents, not a documentation service

Future retrieval or publishing needs may justify a separate product decision. They do not enter the static artifact generator by implication.
